Onboarding Optimization: What Do We Actually Need?

Minimum friction to first adventure — every question costs conversions

Required Information Audit

🎯 Must Have Before Play
Players — Who's playing? (names + classes)
Dice — Physical (which types?) or digital?
⚡ Can Default + Ask Later
Language — Default English, detect from browser, or subtle toggle on Welcome
Account — Defer until after first session ("Save your progress?")
🗑️ Removed for MVP
Adventure selection — Single adventure ("Dungeons & Dragons")
Age ratings — Not needed with one adventure

Streamlined Flow Options

A

2-Screen Flow (Recommended)

Welcome (language toggle in corner) → Party Setup (players + dice) → Play!

Fastest path. Account creation after first session.
B

1-Screen Flow (Most Aggressive)

Welcome + Setup Combined — "Add players" right on welcome screen → Play!

Even faster, but might feel cramped on mobile.
C

Progressive Disclosure

Welcome → Play immediately with default character → Ask for details during natural pauses

Fastest to first scene, but loses party setup moment.

Language Handling Options

A

Browser Detection + Toggle (Recommended)

Auto-detect from browser. Small flag/toggle in Welcome screen corner if user wants to switch.

B

Explicit Choice First

First screen shows two big buttons: "English" / "Dansk" — then proceed.

C

Default English, Change in Settings

Always start English. Danish users find it in settings later.

Account Creation Timing

A

After First Session (Recommended)

"That was fun! Save your progress?" — Create account to keep campaign.

User already experienced value. Higher conversion.
B

Optional on Welcome

"Start Adventure" (no account) vs "Sign In" (returning users)

My Recommendation

Flow A (2 screens) + Language A (browser detect + toggle) + Account A (after first session)
